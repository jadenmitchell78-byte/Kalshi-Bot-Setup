# Kalshi Esports Tracker

Pulls live esports markets from Kalshi's **public, no-auth** market data API
(CS2, League of Legends, Valorant, Dota 2, Overwatch, Call of Duty),
optionally adds basic team context from Liquipedia, and writes a JSON
snapshot to `output/latest.json` on a schedule. That file is the contract
for whatever downstream bot/process you point at it.

**This tool only reads data. It never places orders and never needs your
Kalshi API key.** Order placement is a separate, deliberate step you build
and run yourself, with your own risk limits - see "About the other bot"
below.

## Setup

```bash
cd kalshi_esports_tracker
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Run

```bash
# One-off pull, all games, with Liquipedia enrichment
python main.py

# Loop every 5 minutes
python main.py --loop 300

# Just CS2 and Valorant, no enrichment (faster, fewer external calls)
python main.py --games cs2,valorant --no-enrich

# Loop forever on a schedule, e.g. via cron instead of --loop:
# */5 * * * * cd /path/to/kalshi_esports_tracker && venv/bin/python main.py >> tracker.log 2>&1
```

## Output schema (`output/latest.json`)

```json
{
  "generated_at_utc": "2026-07-16T18:00:00+00:00",
  "source": "kalshi_public_market_data",
  "match_count": 42,
  "matches": [
    {
      "game": "cs2",
      "series_ticker": "KXCS2...",
      "market_ticker": "KXCS2-...-FAZE",
      "title": "FaZe vs Lynn Vision",
      "team_a": "FaZe",
      "team_b": "Lynn Vision",
      "status": "open",
      "close_time": "2026-07-16T20:00:00Z",
      "yes_bid_cents": 55,
      "yes_ask_cents": 57,
      "implied_yes_probability": 0.56,
      "volume": 10935,
      "open_interest": 4200,
      "liquidity": 88000,
      "team_a_context": {"liquipedia_page": "FaZe_Clan", "liquipedia_url": "..."},
      "team_b_context": {}
    }
  ]
}
```

Notes:
- `team_a` / `team_b` are best-effort, parsed from the market title with a
  regex looking for "X vs Y" style patterns. Kalshi's title format isn't
  perfectly consistent across all series, so **always check `title` directly
  if `team_a`/`team_b` come back null** - don't silently drop those matches.
- `implied_yes_probability` is just the bid/ask midpoint converted to a
  0-1 probability. It is the market's current price, not a prediction -
  it moves as people trade.
- `team_a_context` / `team_b_context` are currently just Liquipedia page
  links (free tier). If you want real form/H2H/roster-change stats, swap
  in a paid provider by writing a new class in `stats_providers.py` with
  an `.enrich(game, team_name)` method and using it in `main.py`.

## About "the other bot" that places trades

I built this half deliberately narrow: it's a read-only research/data tool.
Whatever consumes `latest.json` to actually place Kalshi orders is a
separate piece of software you control, and a few things are worth
building into it directly rather than skipping:

- Kalshi order placement requires **authenticated, RSA-signed requests**
  with your own API key - see `docs.kalshi.com/api-reference/portfolio/create-order`.
  Never hardcode that key in a script that also runs unattended market
  scraping; keep it in an env var or secrets manager only the trading
  process reads.
- Add a hard position-size and daily-loss cap before you let anything
  place live orders automatically - prediction markets on live esports
  are thin, and mispriced/parsed team names (see the note above) can
  cause a bot to bet on the wrong side of a match.
- Consider a `--dry-run` mode in that bot first: log what it *would* have
  bet, compare against actual results for a couple weeks, before it
  touches real money.

I'm not a financial advisor and this isn't trading advice - just
flagging the practical failure modes I'd want guarded against.
